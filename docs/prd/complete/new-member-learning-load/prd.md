# PRD: 신규회원 가입 이후 토픽 노출 정책

## 상태

- 트래커 항목: `docs/prd/future-work.md`의 T-002.
- 생명주기 폴더: `complete`.
- 구현 방향: 신규회원에게 가입 이전에 쌓여 있던 shared 학습 토픽을 한 번에 노출하지 않고, 가입 이후 추가된 토픽부터 학습 큐와 목록에 보여줍니다.

## 문제

신규 유입 사용자는 이미 누적된 표현 묶음을 한꺼번에 받으면 첫 학습 진입 장벽이 커집니다. 별도의 튜토리얼이나 복잡한 단계적 해금 없이도, 사용자가 가입한 이후 앱에 추가된 토픽만 보여주면 첫 화면과 `/memorize` 큐가 자연스럽게 작아집니다.

## 목표

- 로그인 사용자의 가입 시각을 서버 사용자 컨텍스트에 포함합니다.
- 비소유 shared 토픽은 `expression_days.created_at`이 가입 시각 이후인 경우에만 표시합니다.
- `/memorize`, `/expressions`, 홈 최근 토픽/통계가 같은 토픽 노출 기준을 사용합니다.
- 본인이 만든 토픽은 가입 시각 필터와 무관하게 계속 볼 수 있습니다.
- 새 DB 컬럼이나 마이그레이션 없이 기존 `auth.users.created_at`과 `expression_days.created_at`만 사용합니다.

## 비목표

- 전체 온보딩 튜토리얼 구축
- 카드 수 기반 단계적 해금/레벨 시스템
- 기존 topic 데이터 마이그레이션
- 푸쉬 알림, streak, 랭킹, 결제, 관리자 UI
- 표현별 개별 가입 컷오프 정책

## 정책

### 가입 컷오프

- 컷오프 기준은 Supabase auth user의 `created_at`입니다.
- 앱 내부에서는 `UserIdentity.createdAt`으로 전달합니다.
- 테스트/로컬 등 가입 시각을 알 수 없는 사용자는 기존 동작을 유지합니다.

### 토픽 노출 기준

토픽은 다음 중 하나면 보입니다.

1. 현재 사용자가 직접 소유한 토픽입니다.
2. 사용자의 가입 시각을 알 수 없습니다.
3. 토픽의 `created_at`이 사용자의 가입 시각과 같거나 이후입니다.

그 외 shared 토픽은 목록, 암기 큐, 홈 요약에서 제외합니다.

### 적용 표면

- `/memorize`: 가입 이전 shared 토픽의 표현은 큐에 들어오지 않습니다.
- `/expressions`: 가입 이후 토픽만 토픽 목록/필터에 표시됩니다.
- `/`: 통계와 최근 표현 묶음은 같은 기준을 사용합니다.
- 표현 상세 조회는 숨겨진 토픽에 속한 표현이면 접근하지 못한 것처럼 처리합니다.

## 성공 기준

- 신규 사용자는 가입 이전 shared 토픽을 `/memorize` 큐에서 보지 않습니다.
- 신규 사용자는 가입 이후 shared 토픽을 정상적으로 봅니다.
- 토픽 목록과 홈 통계가 암기 큐와 같은 기준을 사용합니다.
- 가입 시각이 없는 테스트/레거시 컨텍스트는 기존처럼 모든 readable 토픽을 봅니다.
- DB schema 변경 없이 동작합니다.

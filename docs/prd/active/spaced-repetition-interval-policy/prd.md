# PRD: 암기 큐 간격 반복 정책

## 상태

- 트래커 항목: `docs/prd/future-work.md`의 T-003.
- 생명주기 폴더: `active`; PR #5에서 구현이 진행 중입니다.
- 기준 문서: `docs/prd/complete/daily-expression-memorization/prd.md`.
- 테스트 스펙: 구현 PR의 스케줄링, 메모리 저장소, 암기 카드 집중 테스트로 검증합니다.
- 구현 계획: PR #5의 좁은 SRS 정책 변경 범위가 승인된 구현 범위입니다.

## 문제

표현 수가 늘어날수록 암기 큐의 복습 부담이 줄어야 합니다. 이전 정책에서는 익숙한 카드라도 `모름`을 누르면 장기 복습 간격이 줄어들어 부담이 커졌고, 두 버튼만으로는 “아예 다시 봐야 함”과 “외우긴 했지만 어려움”을 구분하기 어려웠습니다. 학습자에게 필요한 것은 판단 부담이 크지 않은 세 버튼(`다시`, `어려움`, `쉬움`)으로, 틀린 카드는 오늘 다시 보고 어려운 카드는 짧게 유지하며 쉬운 카드는 더 긴 간격으로 늘리는 단순한 에빙하우스 기반 SRS 정책입니다.

## 목표

- 암기 결과 버튼을 `다시 / 어려움 / 쉬움` 세 개로 구성합니다.
- 버튼에 다음 복습 시점을 명시합니다.
- `다시`는 저장된 간격을 줄이지 않고 오늘 다시 보는 처리로만 둡니다.
- `어려움`은 외우긴 했지만 어렵다고 보고 현재 간격을 유지합니다.
- `쉬움`은 쉽게 떠올렸다고 보고 다음 ladder 간격으로 늘립니다.
- 새 의존성이나 스키마 변경 없이 기존 progress 필드로 처리합니다.
- `다시` 카드를 현재 세션 큐 뒤로 보내고, 외울 때까지 다시 노출하는 기존 세션 동작을 유지합니다.

## 비목표

- FSRS/SM-2의 ease factor, difficulty, stability를 추가하지 않습니다.
- Anki식 `다시 / 어려움 / 좋음 / 쉬움` 4버튼 UX를 추가하지 않습니다.
- 푸시 알림이나 리마인더를 추가하지 않습니다.
- 새 DB 컬럼이나 마이그레이션을 추가하지 않습니다.
- 세 버튼 배치와 보조 문구 외에 암기 카드 레이아웃을 재설계하지 않습니다.

## 정책

### 간격 ladder

다음 제한된 ladder를 사용합니다.

```text
1일 → 3일 → 7일 → 14일 → 30일 → 60일 → 90일
```

간격은 `90일`에서 상한 처리합니다.

### 버튼 의미

| 버튼 | 코드 결과 | 저장되는 `last_result` | 카운터 | 큐 동작 | 다음 표시 |
| --- | --- | --- | --- | --- | --- |
| `다시` | `again` | `unknown` | `unknown_count + 1` | 현재 세션 큐 뒤로 이동 | `오늘 다시` |
| `어려움` | `hard` | `known` | `known_count + 1` | 큐에서 제거 | `{현재/최소 간격}일 뒤` |
| `쉬움` | `easy` | `known` | `known_count + 1` | 큐에서 제거 | `{다음 간격}일 뒤` |

기존 코드/테스트 호환을 위해 과거 결과값 `unknown`은 `again`처럼, `known`은 `easy`처럼 처리할 수 있습니다. 다만 새 UI에서는 `again / hard / easy`를 사용합니다.

### `다시` 동작

학습자가 `다시`를 누르면 다음처럼 처리합니다.

1. 저장된 `interval_days`를 그대로 유지합니다.
2. 표현이 오늘 즉시 다시 복습 대상에 남도록 `due_at = null`로 설정합니다.
3. 현재 브라우저 큐에서는 기존 세션 동작처럼 카드를 뒤로 보냅니다.
4. 첫 `다시`나 같은 날 반복 `다시` 모두 간격을 강등하지 않습니다.

예시:

| 이전 간격 | `다시` 후 간격 | 다음 표시 |
| ---: | ---: | --- |
| 90 | 90 | `오늘 다시` |
| 60 | 60 | `오늘 다시` |
| 30 | 30 | `오늘 다시` |
| 14 | 14 | `오늘 다시` |
| 7 | 7 | `오늘 다시` |
| 3 | 3 | `오늘 다시` |
| 1 | 1 | `오늘 다시` |
| 0 | 0 | `오늘 다시` |

### `어려움` 동작

학습자가 `어려움`을 누르면 다음처럼 처리합니다.

1. 외우긴 했지만 어렵다고 보고 `known_count`를 올립니다.
2. 현재 `interval_days`를 유지합니다.
3. 단, 새 카드나 아직 간격이 `0`인 카드는 최소 `1일` 뒤로 예약합니다.
4. 선택된 간격의 한국 시간 자정 경계로 `due_at`을 설정합니다.
5. 서버 갱신 후에는 카드를 활성 큐에서 제거합니다.

예시:

| 이전 상태 | 동작 | 새 간격 | 다음 표시 |
| --- | --- | ---: | --- |
| 새 카드 | `어려움` | 1 | `1일 뒤` |
| 14일 카드 | `어려움` | 14 | `14일 뒤` |
| 30일 카드 | `어려움` | 30 | `30일 뒤` |
| 90일 카드 | `어려움` | 90 | `90일 뒤` |
| `다시` 후 14일 카드 | `어려움` | 14 | `14일 뒤` |

### `쉬움` 동작

학습자가 `쉬움`을 누르면 다음처럼 처리합니다.

1. 이전 저장 결과가 `unknown`이 아니면 ladder의 다음 더 큰 간격으로 승급합니다.
2. 한 번도 복습하지 않은 새 카드에서 첫 답변이 바로 `쉬움`이면 `3일` 뒤로 예약합니다.
3. 이전 저장 결과가 `unknown`이면 같은 날 `다시` 후 회복한 것으로 보고, 현재 저장된 간격보다 더 승급하지 않습니다. 단, 새 카드나 아직 학습되지 않은 카드는 최소 `1일`을 사용합니다.
4. 선택된 간격의 한국 시간 자정 경계로 `due_at`을 설정합니다.
5. 서버 갱신 후에는 카드를 활성 큐에서 제거합니다.

예시:

| 이전 상태 | 동작 | 새 간격 | 다음 표시 |
| --- | --- | ---: | --- |
| 새 카드, 이전 `다시` 없음 | `쉬움` | 3 | `3일 뒤` |
| 새 카드, `다시` 1회 이상 후 | `쉬움` | 1 | `1일 뒤` |
| 14일 카드, 이전 `다시` 없음 | `쉬움` | 30 | `30일 뒤` |
| 30일 카드, 이전 `다시` 없음 | `쉬움` | 60 | `60일 뒤` |
| 60일 카드, 이전 `다시` 없음 | `쉬움` | 90 | `90일 뒤` |
| 90일 카드, 이전 `다시` 없음 | `쉬움` | 90 | `90일 뒤` |
| 14일 카드, `다시` 1회 이상 후 | `쉬움` | 14 | `14일 뒤` |

### 버튼 시점 표시

정답을 공개한 뒤 세 버튼 모두 동작과 시점을 함께 보여줍니다.

- `다시` 버튼: `오늘 다시`
- `어려움` 버튼: `{현재/최소 간격}일 뒤`
- `쉬움` 버튼: `{다음 간격}일 뒤`

`어려움`과 `쉬움` 버튼의 시점 표시는 저장 로직과 같은 스케줄링 함수를 사용해야 하며, UI와 저장 데이터가 같은 의미를 가져야 합니다.

### 큐 포함 조건

`/memorize`는 다음 표현을 포함해야 합니다.

- 아직 한 번도 복습하지 않은 표현
- `due_at = null`인 표현
- `due_at <= now`인 표현

미래 `due_at`을 가진 `known` 표현은 큐에 나오면 안 됩니다. 과거 row 중 `last_result = known`이지만 `due_at`이 없는 경우에는 기존 안전 fallback 동작을 유지합니다.

## 데이터 모델

이번 버전에서는 스키마 변경이 필요하지 않습니다.

기존 `expression_progress` 필드를 사용합니다.

- `interval_days` — 현재 ladder 간격 또는 아직 학습/재학습 전인 카드의 `0`.
- `last_result` — DB에는 기존 허용값인 `known` 또는 `unknown`만 저장합니다. `hard`와 `easy`는 모두 `known`으로 저장하고, `again`은 `unknown`으로 저장합니다.
- `due_at` — 큐에 다시 나타나는 시점의 기준값입니다.

## 수용 기준

- 정답이 공개된 암기 카드에는 `다시 / 오늘 다시`, `어려움 / N일 뒤`, `쉬움 / N일 뒤`가 표시됩니다.
- 새 표현을 바로 `쉬움`으로 표시하면 `interval_days = 3`이 되고, 한국 달력 기준 3일 뒤 `due_at`이 설정됩니다.
- 새 표현을 바로 `어려움`으로 표시하면 `interval_days = 1`이 되고, 다음 날 한국 시간 자정 `due_at`이 설정됩니다.
- 새 표현을 `다시`로 한 번 이상 표시한 뒤 `쉬움` 또는 `어려움`으로 표시하면 `interval_days = 1`이 됩니다.
- 30일 표현을 `어려움`으로 표시하면 `interval_days = 30`을 유지합니다.
- 30일 표현을 `쉬움`으로 표시하면 `interval_days = 60`이 됩니다.
- 60일 표현을 `쉬움`으로 표시하면 `interval_days = 90`이 됩니다.
- 90일 표현을 `쉬움`으로 표시하면 `interval_days = 90`으로 상한 상태를 유지합니다.
- 어떤 표현이든 `다시`로 표시하면 이전 `interval_days`를 유지하고 `due_at = null`이 됩니다.
- `다시` 표현은 due 상태로 남고, 클라이언트 큐 뒤로 순환될 수 있습니다.
- 기존 테스트, lint, typecheck, build, 실제 `/memorize` 경로 확인이 통과합니다.
